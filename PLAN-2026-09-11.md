## 1. Fix networking / DNS passthrough

### Problem

The `cellar-resolv` service (`modules/base.nix:19-31`) runs once at boot
(`Type=oneshot`, `RemainAfterExit=true`) and never re-evaluates. After
Wi-Fi switching, sleep/resume, or VPN toggle, `/etc/resolv.conf` points at
a stale gateway. The service also hardcodes public DNS servers (1.1.1.1,
8.8.8.8) as fallbacks, bypassing the WSL DNS proxy that would honor VPN
NRPT policies when `dnsTunneling=true`. A missing guard on an empty
gateway produces an invalid blank `nameserver` line.

Additionally, `localhostForwarding=true` in `.wslconfig.example` is
ignored in mirrored mode (Microsoft confirmed this), and
`hostAddressLoopback` is not set, limiting WSL→Windows service access.

### Changes

#### `modules/base.nix` — rewrite cellar-resolv service

Replace the oneshot service (lines 19-31) with a service + timer pair:

**Service** (`cellar-resolv.service`):
- Type=oneshot (runs the script, which writes resolv.conf)
- Guard: exit 1 if no default route (`ip route show default` returns empty)
- Try the WSL DNS proxy first (`10.255.255.254`), then fall back to
  gateway + public DNS. This respects VPN NRPT policies.

Script body:
```bash
GW=$(ip route show default | awk '{print $3; exit}')
if [[ -n "$GW" ]]; then
    printf 'nameserver 10.255.255.254\nnameserver %s\nnameserver 1.1.1.1\nnameserver 8.8.8.8\n' "$GW" > /etc/resolv.conf
else
    echo "cellar-resolv: no default route, skipping" >&2
fi
```

**Timer** (`cellar-resolv.timer`):
- Runs on boot (`OnBootSec=0`)
- Re-evaluates every 60 seconds (`OnUnitActiveSec=60s`)
- This handles sleep/resume and Wi-Fi switches without `wsl --shutdown`

#### `windows/.wslconfig.example` — add hostAddressLoopback

Add to the `[experimental]` section:
```ini
hostAddressLoopback=true
```

This routes the Windows host's LAN IP back to `127.0.0.1` inside WSL,
improving WSL→Windows service access.

## 2. Fix BORE kernel breaking Docker Desktop

### Problem

Docker Desktop uses a LinuxKit bootstrap (`wsl-bootstrap` → `initd`) that
mounts ISO9660 images. The `bore.fragment` does not include
`CONFIG_ISO9660_FS=y`, so if Microsoft's base config keeps it as `=m`,
the mount fails silently in WSL2 where kernel modules cannot be loaded.
The global `kernel=` in `.wslconfig` applies to the hidden
`docker-desktop` distro too.

### Changes

#### `kernel/bore.fragment` — add ISO9660 built-in

Append after the btrfs line:
```
# Docker Desktop's LinuxKit bootstrap mounts ISO9660 images.
# Built-in (=y), not module: WSL2 never populates /lib/modules/.
CONFIG_ISO9660_FS=y
```

#### `modules/docker.nix` — document Docker Desktop coexistence

Add a comment block explaining:
- Docker Desktop on Windows and native Docker Engine in the cellar
  coexist when WSL2 Integration is disabled in Docker Desktop settings
- The custom kernel applies globally — ISO9660 built-in is the fix
- If WSL2 Integration is enabled, it overrides the native Engine

#### `docs/BORE-SCHEDULER.md` — add Docker Desktop section

New section documenting:
- Why the kernel breaks Docker Desktop (ISO9660 + LinuxKit)
- The fix (bore.fragment already includes it)
- How to disable WSL2 Integration in Docker Desktop
- The `cellar docker-doctor` diagnostic

## 3. Update manager (`cellar update`)

### Problem

`cellar deploy` syncs the repo to `/opt` and rebuilds, but doesn't pull
from git. The user manually `git pull`s on each PC. Need a single command
that pulls, shows what changed, confirms, then deploys.

### Changes

#### `deskbottom/bin/cellar` — add `cmd_update()`

New function with flags:
```
cellar update              # pull + show changes + confirm + deploy
cellar update --inputs     # also nix flake update before deploy
cellar update --dry-run    # pull + report only, no rebuild
cellar update --kernel     # also check BORE patch drift
```

Implementation:
1. Parse flags (`--inputs`, `--dry-run`, `--kernel`)
2. `git -C "$REPO" pull --ff-only` — fail loudly on divergence
3. Show `git log HEAD@{1}..HEAD --oneline` to display what changed
4. If `--dry-run`, stop here
5. Prompt: "Deploy these changes? [y/N]"
6. On confirmation, call existing `cmd_deploy` logic
7. If `--kernel`, run `kernel/check-upstream.sh --quiet` and print drift status
8. Print summary

Register in case statement:
```bash
update) shift || true; cmd_update "$@" ;;
```

Update the usage block at the top of the file to include `update`.

## 4. Terminal desktop via Carbonyl + noVNC

### Problem

The user wants a full OS experience inside the terminal — app management,
desktop with shortcuts, browser, all without touching Windows. The
solution is a nested architecture: headless XFCE desktop → wayvnc →
noVNC → Carbonyl (Chromium in terminal) → Zellij pane.

### Architecture

```
WezTerm (Windows terminal)
  └── Zellij (terminal multiplexer)
       ├── Shell pane (fish)
       ├── Monitor pane (btop)
       ├── Files pane (yazi)
       └── Desktop pane (Carbonyl — Chromium in terminal)
            └── http://localhost:6080/vnc.html (noVNC client)
                 └── XFCE desktop
                      └── labwc (headless Wayland compositor)
                           └── wayvnc (VNC server on :5900)
                                └── websockify (WebSocket proxy on :6080)
```

### Changes

#### New file: `modules/webtop.nix`

Always-on module (no enable toggle). Contents:

**Packages:**
- `labwc` — lightweight Wayland compositor (runs headless)
- `xfce.xfce4-panel`, `xfce.xfce4-settings`, `xfce.xfce4-terminal`,
  `xfce.thunar`, `xfce.xfce4-appfinder`, `xfce.xfce4-taskmanager` —
  XFCE desktop components
- `wayvnc` — VNC server for wlroots compositors
- `websockify` — WebSocket-to-TCP proxy
- `novnc` — HTML5 VNC client (static web files)

**Systemd user services:**

1. `labwc-headless.service`:
   - `WLR_BACKENDS=headless WLR_LIBINPUT_NO_DEVICES=1 labwc`
   - `wantedBy = [ "default.target" ]`
   - Environment: `WAYLAND_DISPLAY=wayland-1`

2. `xfce-session.service`:
   - `xfce4-session`
   - `after = [ "labwc-headless.service" ]`
   - Environment: `WAYLAND_DISPLAY=wayland-1`, `DISPLAY=:0` (XWayland)

3. `wayvnc.service`:
   - `wayvnc --output=wayland-1 0.0.0.0 5900`
   - `after = [ "labwc-headless.service" ]`

4. `websockify.service`:
   - `websockify --web=${pkgs.novnc}/share/novnc 6080 localhost:5900`
   - `after = [ "wayvnc.service" ]`

All services: `Restart = "on-failure"`, run as the logged-in user.

#### `flake.nix` — wire in webtop module

Add `./modules/webtop.nix` to the modules list at line 44 (after
`./modules/docker.nix`). Always loaded, no enable toggle.

#### `modules/packages.nix` — add carbonyl

Add `carbonyl` to the package list (under a new `# Web (terminal)` comment
block).

#### `deskbottom/bin/cellar` — add `cmd_webtop()`

New function:
```bash
cmd_webtop() {
    local url="http://localhost:6080/vnc.html"
    if in_zellij; then
        zellij action new-pane --close-on-exit -- bash -lc "carbonyl $url"
    else
        exec carbonyl "$url"
    fi
}
```

Register in case statement:
```bash

```

Update usage block to include `webtop`.

Add:
```toml

```

Key `b` chosen for "browser/desktop".

## 10. Fish greeting customization

### Problem

The default fish greeting prints `"Welcome to fish, version X.Y.Z!"` on
every interactive session. The repo already builds a MOTD (`/etc/motd`
with the RootCellar wordmark + "Welcome to the cellar." + Raddix art) but
never displays it.

### Changes

#### `modules/deskbottom.nix` — add fish_greeting function

Add to `interactiveShellInit`, before the existing `set -gx CELLAR_HOME`:

```fish
set -g fish_greeting ""
function fish_greeting
    if test -t 1
        cat /etc/motd
    end
end
```

This suppresses the default version banner and shows the cellar MOTD
instead. The `test -t 1` guard skips it for non-interactive/piped
contexts.

## 11. Portability — remove hardcoded `randy` references

### Problem

The username `randy` is hardcoded across 11 files. Anyone forking
RootCellar must manually find-and-replace every occurrence. The scripts
should derive the Windows username at runtime.

### Strategy

- `modules/base.nix` is the **single source of truth** for the username.
  New users change `randy` there before first deploy.
- All scripts derive paths at runtime via `$(whoami)`, which returns the
  Linux username that matches the Windows username in WSL2.
- Zellij layouts use `$HOME` for `cwd` instead of hardcoded paths.
- `.wslconfig.example` uses `<you>` placeholder with a comment.

### Changes

#### `deskbottom/bin/cellar:20` — dynamic REPO path

```bash
REPO="/mnt/c/Users/$(whoami)/Documents/Projects/rootcellar"
```

#### `kernel/build-kernel.sh:26` — dynamic INSTALL_TO

```bash
INSTALL_TO="/mnt/c/Users/$(whoami)/wsl-kernel"
```

#### `migrate/export-home.sh:13` — dynamic default output

```bash
OUTPUT_DIR="${1:-/mnt/c/Users/$(whoami)}"
```

#### `migrate/export-opencode.sh:14` — dynamic default output

```bash
OUTPUT_DIR="${1:-/mnt/c/Users/$(whoami)}"
```

#### `migrate/post-reboot.sh` — dynamic paths

- Line 19: `REPO="/mnt/c/Users/$(whoami)/Documents/Projects/rootcellar"`
- Line 70: `ls -t /mnt/c/Users/$(whoami)/opencode-backup-*.tar.gz`
- Line 87: `wsl.exe -d "$NEW_NAME" -u root -- ls -la /home/$(whoami)/.local/share/opencode/`
- Line 99: `cd C:\Users\$(whoami)\Documents\Projects\rootcellar\windows`

Note: `$(whoami)` inside a bash script works. For the PowerShell
reference on line 99, use a comment with `<you>` since that line is
echoed instructions, not executed.

#### `windows/.wslconfig.example:8` — placeholder

```ini
kernel=C:\\Users\\<you>\\wsl-kernel\\bzImage
```

Add a comment: `# Replace <you> with your Windows username.`

#### `windows/defender-exclusions.ps1:27` — dynamic default

```powershell
[string]$UserName = $env:USERNAME
```

Remove the hardcoded `"randy"` default. The comment on line 18 should
say `Default: current user` instead of `Default: randy`.

#### `deskbottom/zellij/layouts/main.kdl` — replace cwd paths

Replace all `cwd "/mnt/c/Users/randy"` with `cwd "$HOME"`.

Zellij expands environment variables in `cwd` directives. `$HOME`
resolves to `/home/randy` which is correct for all pane types. For
Windows-side paths (like opencode project dirs), use the pattern:
`cwd "/mnt/c/Users/$(whoami)/Documents/Projects/..."` — but since
KDL doesn't support shell expansion, these should use `$HOME` relative
paths or be documented as needing manual adjustment.

Actually, Zellij does NOT expand env vars in KDL `cwd`. The correct
approach is to use `~` which Zellij does resolve, or leave the default
cwd (inherits from parent). Let me verify and adjust.

**Revised approach for main.kdl:** Since `main.kdl` is a personal
layout (not the default `cellar.kdl`), and KDL doesn't expand env
vars, the hardcoded paths are acceptable in a personal layout. The
**default** `cellar.kdl` layout has no hardcoded paths and is already
portable. Document that `main.kdl` is a personal layout that may
need editing.

#### `modules/base.nix` and `modules/docker.nix` — keep as-is

These define the user. They MUST be explicit. This is the one place
where `randy` lives, and new users change it here.
